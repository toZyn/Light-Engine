# Separate image overlay addon

User clarification: display compatibility means split-screen/freeform OS windows beside other apps, monitor choice and size adaptation. It does not require several simultaneous native game windows. The addon must place a mod-supplied image above the home screen/other applications; it must not read wallpaper or insert a background inside gameplay.

Architecture: separate screen-overlay Lua addon; Android companion package com.zyn.lightengine.overlay owns its own SYSTEM_ALERT_WINDOW permission and native WindowManager window. No engine permission/renderer injection. Original PNG bytes cross a custom URI, max256KiB to stay below Binder transaction limits; larger images fail explicitly without quality reduction. A translucent/nonfocusable draggable image window has an always-accessible close action; specialUse foreground service with Stop notification owns lifecycle. User consent is per image and Android grant is checked before activation; hide requires the matching session token. Decode off UI, guard decoded dimensions/pixels and cleanup native resources.

Windows/Linux companion uses PySide6 translucent topmost window plus consent-paired loopback API. Original PNG max8MiB. Token authorized only after native consent; unauthenticated image requests fail. Windows/Linux URI handler installation is an explicit setup step; Wayland limitations must be reported honestly. No desktop fallback is called an OS permission grant.

API/protocol: lightengine-overlay://show?token=64hex&image=base64urlPNG&label=percentencoded&x=int&y=int&width=int&height=int; hide?token. Desktop connect?token&label then loopback127.0.0.1:51874 POST /image (Bearer token, original PNG) and DELETE /image. Image constraints: width,height<=4096, pixels<=16million. Requests acknowledge delivery/permission-pending, never pretend a window was displayed before consent. User label is plain text.

Existing core display improvements remain shared across OSs, with Android manifest resizable=true. Physical Redmi/Windows execution is not available; distinguish build/test results from device testing.
